## 2. P0：值得现在补的四项（合计约 3 小时）

### 2.1 结构化日志（1h）

现在：`logging.basicConfig` 纯文本，错误日志里手写 `trace_id=xxx`。
问题：面试官问"线上怎么查一个请求的完整日志"，只能说"grep trace_id"——能用，但不像工程化。

做法：`app/infra/logging.py`，`TDP_LOG_FORMAT=json|text`
- JSON 字段：`ts / level / logger / msg / trace_id / request_id / method / path / status / duration_ms`
- 从 `contextvars` 取 trace_id（已存在），不额外传参
- text 格式保留为默认（本地看日志舒服），线上用 `TDP_LOG_FORMAT=json`

**收益**：三支柱补齐；"日志里能按 trace_id 串起一次请求"是可演示的。

### 2.2 优雅停机（1h）

现在：uvicorn 收到 SIGTERM 直接断；worker 正在处理的消息可能处理一半。
问题：**滚动发布/重启会丢 in-flight 请求**，这是生产环境的基本功。

做法：
- app：`lifespan` 里挂 shutdown 钩子，把 `_ready` 置 False（`/readyz` 立刻 503），
  等 in-flight 计数归零（已有请求计数？没有就加个计数器）
- worker：SIGTERM 后不再取新消息，处理完当前这条再退出
- 验证：发一个慢请求 + 同时 `Ctrl+C`，看它是否跑完

**收益**：面试问"发布时会不会丢请求/丢消息"能答且能演示。

### 2.3 覆盖率（20 分钟）

```
pip install pytest-cov
python -m pytest --cov=app --cov-report=term-missing
```
把数字写进 README。预期不算高（集成测试多、CLI 脚本不在 app 里），但**有数字 > 没数字**。

### 2.4 依赖与密钥扫描进 CI（30 分钟）

```yaml
- run: pip install pip-audit && pip-audit -r requirements.txt
- uses: gitleaks/gitleaks-action@v2
```
**收益**：供应链安全是"工程化"的硬证据，且几乎零成本。

## 4. 不做的四项：面试话术（照这个说，不掉分）

| 追问题 | 怎么答 |
|---|---|
| 有 token 刷新/登出吗？ | "没有。内部工具、单服务，TTL 1 小时，过期重新登录。要做刷新得引 refresh 轮换 + 黑名单，那是另一套复杂度，收益不匹配。" |
| 为什么不做字段级权限？ | "权限做到项目级就停了，业务边界就是项目。再往下是字段级策略（OPA/Casbin），会为一个不存在的需求引入策略引擎。" |
| 限流为什么不分租户？ | "项目 ≠ 租户，硬造租户模型只是为了讲'分布式'，属于自己骗自己。" |
| 有备份/SLO/长稳压测吗？ | "备份：演示数据可 `--drop` 重建，生产要 pg_dump + WAL 归档，我没做但知道路径。压测：1000 并发是 service 层验正确性，HTTP 层压到 50 并发测 P99，没做长稳。" |

**主动说"没做"比被问出来好**：这些都写在 README 的欠账表里。
