# 部署（把项目变成"面试官能点开的链接"）

> 目标：一台机器上 `docker compose` 起全套，`http://<IP>/ui/` 可以点。
> 全套 = app + worker + scheduler + PostgreSQL + Redis；Nginx 反代 80/443。

## 0. 为什么值得部署

| 收益 | 说明 |
|---|---|
| 简历能写**可访问链接** | 面试官/HR 能直接点开，比截图可信 |
| 面试有话题 | 容器化、迁移、反代、健康检查、密钥管理，都能被追问且答得上 |
| 倒逼工程化 | 这套东西你本地跑过 200 次，但"换个环境还能跑"是另一回事 |

**不需要域名**：用 `http://IP/ui/` 就够，免备案。有域名再上 HTTPS。

## 1. 机器与依赖

- 1 核 2G 起步（学生机即可）；Postgres 吃内存，2G 是舒适下限
- Ubuntu 22.04 / 24.04，装 Docker：
  ```bash
  curl -fsSL https://get.docker.com | sh
  sudo usermod -aG docker $USER && newgrp docker
  ```

## 2. 三步起服务

```bash
git clone <你的仓库> tdp && cd tdp
cp .env.example .env

# 生成并填入密钥（两处：TDP_JWT_SECRET / POSTGRES_PASSWORD）
python3 -c "import secrets; print(secrets.token_urlsafe(48))"
vim .env

./deploy/deploy.sh          # 构建 + 启动 + 等就绪 + 上线自检
```

看到 `可以对外开放了` 就成功。界面：`http://<IP>:8000/ui/`（还没配 Nginx 时）。

## 3. Nginx + HTTPS（可选但推荐）

```bash
sudo apt install -y nginx
sudo cp deploy/nginx/tdp.conf /etc/nginx/conf.d/tdp.conf
sudo nginx -t && sudo systemctl reload nginx

# 有域名才做这一步
sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d your.domain.com
```

配完之后：`http://<IP>/ui/`，`/metrics` 只允许本机访问。

## 4. 管理员口令与只读演示账号

`.env` 里设 `TDP_ADMIN_PASSWORD`，`migrate` 灌库时 admin 的初始口令就是它，
而不是代码里那个众所周知的默认值 —— 这比"上线后记得改"可靠。

`.env` 里填：

```ini
TDP_DEMO_USER=demo
TDP_DEMO_PASSWORD=<你能公开的弱口令>
```

`migrate` 服务会把它建成 **viewer**：能看三个页面和所有列表，**任何写操作返回 403**。

为什么不用 admin 演示：公网上谁都能点的 admin 等于没有权限；而且演示账号被点乱了，
你面试时打开发现数据是别人造的，很尴尬。

## 5. 上线自检（每次改配置都跑）

```bash
python scripts/prod_check.py --base-url http://127.0.0.1:8000
```

会逐条检查：

| 检查项 | 为什么 |
|---|---|
| JWT 密钥长度与强度 | 弱密钥 = 任何人能伪造 admin token |
| `TDP_AUTH` 是否关闭 | 关掉后匿名按 admin 放行 |
| 数据库口令 | 弱口令 + 端口暴露 = 拖库 |
| 限流后端是否 Redis | 否则多副本各限各的 |
| 匿名访问是否被拦 | 401 才对 |
| **默认 admin 口令是否已改** | `admin/Admin@12345` 能登录就是 FAIL |
| 演示账号是 viewer 且写不动 | 403 才对 |
| `/ui` 是否打得开 | 镜像里漏拷 `web/dist` 时这里会 404 |

## 6. 保活（免费层 / 休眠）

```bash
# 每 5 分钟探一次，避免 PaaS 免费实例休眠
*/5 * * * * curl -fsS http://127.0.0.1:8000/healthz >/dev/null || true
```

## 7. 重置演示数据

被点乱了、或者想回到干净状态：

```bash
docker compose -f docker-compose.prod.yml run --rm migrate \
  python scripts/init_db.py --drop --seed-demo
```

⚠️ `--drop` 会**删库重建**，只用于演示环境。

## 8. PaaS 路线（Render / Railway / Fly.io）

- 用仓库里的 `Dockerfile`（已含前端构建），不用改
- 数据库/Redis 用平台托管，把 `TDP_DATABASE_URL` / `TDP_REDIS_URL` 指向托管实例
- 注意：免费实例会休眠，首次打开可能等 20~40 秒；面试前先自己点一下预热
- Render 的免费 Postgres 有有效期，过期会删库——演示前确认还在

## 9. 排错

| 现象 | 原因 |
|---|---|
| `/ui/` 404，但 `/docs` 正常 | 镜像里没 `web/dist`：确认 Dockerfile 有 `COPY --from=web /web/dist` |
| 502 | app 没起来：`docker compose -f docker-compose.prod.yml logs --tail=80 app` |
| `/readyz` 一直 degraded | 库没迁：看 `migrate` 服务日志 |
| 打开页面空白 | 构建产物 `base` 不是 `/ui/`（见 README 踩坑 38） |
| 登录 401 | 演示账号没建：检查 `.env` 的 `TDP_DEMO_USER/PASSWORD` 后重启 migrate |
